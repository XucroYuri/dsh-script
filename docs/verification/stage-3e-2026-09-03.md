## Scope

Stage 3E establishes a testable JWT verification boundary:

- fixed HTTPS issuer/JWKS source and audience;
- RS256-only RSA signature verification selected by `kid`;
- issuer, audience, subject, expiration, issued-at and not-before validation with bounded clock skew;
- Team/member mapping only after signature and trust-claim verification;
- no token-supplied key URL or unsupported critical header, plus bounded JWKS caching and forced refresh.

The validation rules follow the OIDC Core ID Token requirements for issuer, subject, audience, expiration, issued-at and signatures, with JWS compact/key-id handling defined by the JOSE standards.
